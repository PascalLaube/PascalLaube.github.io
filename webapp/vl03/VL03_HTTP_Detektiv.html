🕵️ HTTP-Detektiv

VL 03 · Das Web und seine Protokolle · Web-Applikationen · WS 2026/27

So geht's: Arbeitet zu zweit, ein Laptop mit Browser und Terminal reicht. Ihr untersucht echte Webseiten mit den DevTools und mit curl. Zu jeder Aufgabe steht, welche der sechs Stationen aus der Vorlesung ihr gerade beobachtet. Eure Antworten schreibt ihr in die Felder. Sie bleiben nur in diesem Browser gespeichert, mit dem Knopf unten könnt ihr sie als Textdatei sichern.
Vorbereitung (1 Minute): Öffnet Chrome, Edge oder Firefox, drückt F12 und wechselt in den Tab Network. Setzt den Haken bei Preserve log, damit Umleitungen nicht verschwinden. Rechtsklick auf eine Spaltenüberschrift → Protocol einblenden.
Station 5 · HTTP

1 · Die erste Anfrage ca. 7 Min

Ruft eine Seite eurer Wahl auf (z. B. https://www.htwg-konstanz.de, https://github.com oder euer Lieblingsshop) und ladet sie ohne Cache neu: Strg+Shift+R (macOS: Cmd+Shift+R).

  1. Welche Methode und welchen Statuscode hat die allererste Anfrage?
  2. Wie viele Anfragen braucht die Seite insgesamt, und wie viele Daten werden übertragen? (Statuszeile unten im Network-Tab.)
  3. Welches Protokoll nutzt die Seite: http/1.1, h2 oder h3?
  4. Welchen Content-Type hat die erste Antwort, welchen eine CSS-Datei?
Station 6 · Cache

2 · Caching entschlüsseln ca. 8 Min

  1. Sucht eine CSS- oder JS-Datei. Welchen Cache-Control-Header hat sie? Wie lange darf sie im Cache bleiben?
  2. Hat sie einen Hash im Dateinamen (etwa app.f3a9c1.js oder merged-7c99adcc….css)? Warum darf sie dann so lange gecacht werden?
  3. Welchen Cache-Control-Header hat die HTML-Seite selbst? Warum ist er anders?
  4. Ladet die Seite jetzt normal neu (F5). Was steht nun in der Spalte Size bzw. Transferred? Wie viele Daten werden jetzt noch übertragen?

Header findet ihr nach einem Klick auf die Anfrage im Tab Headers unter Response Headers.

Station 2 · DNS und Station 5 · HTTP

3 · Umleitungen und ein Rätsel ca. 8 Min

  1. Tippt im Browser http://www.htwg-konstanz.de ein, mit http, ohne s. Welcher Statuscode steht beim ersten Eintrag im Network-Tab? Klickt ihn an: Was steht im Header Non-Authoritative-Reason? Wer hat hier eigentlich umgeleitet, der Server oder euer Browser?
  2. Fragt dieselbe Adresse jetzt ohne Browser ab: curl.exe -I http://www.htwg-konstanz.de (macOS, Linux: curl -I …). Welchen Statuscode schickt der Server? Ist das eine dauerhafte oder eine vorübergehende Umleitung, und welche wäre hier besser?
  3. Jetzt htwg-konstanz.de ganz ohne www. Was passiert? An welcher der sechs Stationen scheitert die Anfrage? Prüft eure Vermutung im Terminal mit nslookup htwg-konstanz.de und nslookup www.htwg-konstanz.de.
Station 5 · HTTP ohne Browser

4 · HTTP mit curl ca. 7 Min

curl ist auf Windows 10 und 11, macOS und Linux vorinstalliert. Öffnet ein Terminal. Windows: Schreibt in der PowerShell immer curl.exe, nicht curl. Ohne .exe startet die PowerShell ein ganz anderes Programm und meldet seltsame Fehler.

curl.exe -v https://www.htwg-konstanz.de -o NUL    # Windows
curl -v https://www.htwg-konstanz.de -o /dev/null  # macOS, Linux
  1. Markiert in der Ausgabe die Request-Zeile, den Host-Header und die Statuszeile. Woran erkennt ihr, welche Zeilen zur Anfrage und welche zur Antwort gehören?
  2. Die Zeilen mit * sind Meldungen von curl selbst. Welche davon gehören zu TLS? Das Zertifikat seht ihr am einfachsten im Browser: Klick auf das Symbol links neben der Adresse, dann „Verbindung ist sicher“ und „Zertifikat ist gültig“. Wer hat es ausgestellt, für welche Namen gilt es, und bis wann?
  3. Fragt eine Seite ab, die es nicht gibt: curl.exe -I https://www.htwg-konstanz.de/gibt-es-nicht. Welcher Code kommt?
  4. Warum lädt curl nur eine Datei, während der Browser in Aufgabe 1 Dutzende Anfragen gestellt hat?

macOS und Linux: einfach curl statt curl.exe.

Bonus, falls ihr früher fertig seid

5 · Eure eigene Seite

Startet euren M1-Prototyp über einen lokalen Server statt per Doppelklick, z. B. im Projektordner mit python -m http.server 8000 oder npx serve. Öffnet http://localhost:8000.

  1. Gibt es im Network-Tab ein rotes 404? Welche Datei fehlt? (Ein 404 für favicon.ico ist normal, wenn ihr kein Favicon habt: Der Browser fragt von sich aus danach.)
  2. Ladet mit F5 neu. Wo seht ihr jetzt 304?
